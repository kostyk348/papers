== 6. what the port does not claim

- The seconds are not the same and are not meant to be: `protorun` is a native binary and the
  timing metrics measure the subject server, but the wall clock around each call also includes the
  harness's own I/O. The card allows the timing fields to differ, and the parity tool treats them as
  equal when the order of magnitude matches.
- The port reproduces the *reports*, i.e. the measurement path. The two reports it reproduced were
  produced by the earlier revision of `code/run_protocol.py` (0.3.0); the 0.4.0 change to that file
  touches only how it validates its output, not how it measures, and the parity check is therefore
  still a check of the measurement path.
- `code/run_protocol.py` and `code/streams.py` were **not deleted**. They are named by
  `protocol.md`, `README.md` §4b and the two committed `summary.md` files, so removing them means
  rewriting those references; until that follow-up happens the frozen, byte-identical copy in
  `evidence/pre-port-runner/` is the archival one and `tools/protorun` is the tool of record.
- The Python SDK version pinned in the two committed reports is 1.9.4; the parity runs used the same
  1.9.4 (unpacked into `tools/protorun/target/mcp-1.9.4-site`, never installed into a shared
  environment), which is why the reports agree down to `serverInfo.version` in the raw logs.

== 7. reproduce all of it

```bash
cd <package root>
cd tools/protorun && cargo build --release && cd ../..          # no crates, no network, ~30 s

PYP="<python that the server runs under>"                        # recorded in each report's disclosure
PYPATH="tools/protorun/target/mcp-1.9.4-site"                    # mcp 1.9.4 site dir
SR="<dir with the read-only server clones>"                      # refs/

tools/protorun/target/release/protorun parity streams \
    --reference reports/sint-liquid-mcp-2026-10-16 --server sint-liquid-mcp
tools/protorun/target/release/protorun run --server sint-liquid-mcp \
    --server-root "$SR" --server-python "$PYP" --server-pythonpath "$PYPATH" \
    --seeds 1,2,3 --out reports/parity-rust --run-name sint-liquid-mcp-2026-10-16
tools/protorun/target/release/protorun parity run-vs-report \
    --reference reports/sint-liquid-mcp-2026-10-16 \
    --run reports/parity-rust/sint-liquid-mcp-2026-10-16
```

The mcp 1.9.4 site directory is a `pip install --target` into the ignored build directory
(`python -m pip install --target tools/protorun/target/mcp-1.9.4-site "mcp==1.9.4" "pydantic==2.13.4"`;
pydantic 2.13.4 rather than the newest release, because mcp 1.9.4 imports
`pydantic._internal._typing_extra.eval_type_backport`, which newer pydantic versions no longer
export). Nothing was installed into a shared environment and nothing large was written outside
`tools/protorun/target/`.
