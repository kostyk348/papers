## 1. Surveys that define the current state

The 2026 surveys set the frame this paper answers. `\cite{huan2026secondhalf}` organises agent
memory along three dimensions — memory substrate (internal/external), cognitive mechanism
(episodic, semantic, sensory, working, procedural) and memory subject (agent- vs. user-centric)
— and reviews evaluation benchmarks and metrics. `\cite{zhou2026agentnative}` is closer to our
problem statement: memory has "evolved from simple retrieval-augmented mechanisms into a data
management system that supports persistent information storage, retrieval, update,
consolidation, and dynamic lifecycle governance", while "existing evaluations still benchmark
agent memory mainly through end-to-end task success metrics (e.g., F1, BLEU), while treating
the underlying system as a monolithic black box"; they respond with a four-module analytical
framework (representation/storage, extraction, retrieval/routing, maintenance) and an
experiment over 12 systems and 11 datasets. `\cite{zhou2026externalization}` frames memory as
one of three externalisation channels (memory, skills, protocols) and lists evaluation and
governance as open challenges. `\cite{zhang2024memorysurvey}` remains the entry point for
memory-mechanism vocabulary in agents.

**What we take:** the operation list is incomplete without maintenance/consolidation, so our
taxonomy keeps a consolidation operation and a lifecycle axis.
**What we change:** both surveys organise memory by *type* or by *internal module*. Neither
publishes an interface-level operation contract that a third party can run against a server it
did not write; that is what §3 of the paper adds, and it is why the report format
(`protocol.md` §5) is part of the contribution rather than an appendix.

## 2. Agent-memory systems and their operations

The systems that give the taxonomy its per-operation examples:

- **Operating-system analogy.** `\cite{packer2023memgpt}` (MemGPT, continued as Letta,
  `\cite{lettadocs}`) introduces virtual context management with main/external storage tiers
  and self-editing memory blocks. Write and read are explicit; revision is implicit (a block
  is rewritten in place) and there is no separate intention store.
- **Observational agents.** `\cite{park2023generative}` adds the memory stream with
  recency/importance/relevance retrieval and reflection — a genuine consolidation operation
  with no revision semantics. `\cite{zhong2023memorybank}` adds decay and user portraits.
  `\cite{wang2023scm}` makes memory control explicit for long inputs.
- **Read-write memory units.** `\cite{modarressi2023retllm}` equips the model with a general
  read-write memory unit — the closest prior interface-level framing, and still without
  revision, intent, or epistemic status.
- **Agentic organisation.** `\cite{xu2025amem}` constructs notes, links them, and *evolves*
  existing notes (a write that mutates prior records); `\cite{zhou2024structural}` shows that
  the choice of memory structure changes task outcomes, which is an argument for reporting
  structure alongside operations.
- **Production stores.** `\cite{chhikara2025mem0}` extracts, consolidates and retrieves salient
  facts and reports accuracy/cost/latency; `\cite{rasmussen2025zep}` keeps a temporal knowledge
  graph with validity intervals and reports latency and accuracy against MemGPT;
  `\cite{li2025memos}` treats memory as a managed resource; `\cite{xu2026linkedin}` and
  `\cite{alake2026oracle}` report industrial requirements (latency, scoping, durability,
  procedural knowledge); hosted assistant memory (`\cite{openaimemory2024}`) exposes
  user-visible saved memories plus derived chat history, with opt-out controls.
- **Neurocognitive designs.** `\cite{gutierrez2024hipporag}` (hippocampal indexing),
  `\cite{mody2026cranimem}` (gated, bounded, distractor-resistant memory),
  `\cite{song2026dmem}` (dopamine-gated routing by reward prediction error),
  `\cite{feng2026baremem}` (Bayesian reliability of advisors).
- **Multi-agent and shared memory.** `\cite{rezazadeh2025collabmem}` (multi-user sharing with
  dynamic access control), `\cite{li2025maas}` (purpose-bound memory mediation),
  `\cite{shu2024genaimalti}` (design and evaluation of enterprise multi-agent collaboration,
  the setting in which shared memory lives).
- **Cost as a design constraint.** `\cite{song2026dmem}` reports O(N²) write latency and
  excessive token cost for append-and-evolve designs; `\cite{zhou2026agentnative}` finds
  localised maintenance cheaper than global reorganisation. `\cite{gaikwad2026routing}`
  formulates retrieval as store routing and scores it with coverage, exact match and token
  efficiency; `\cite{lin2025sleeptime}` moves work offline.

**What we take:** each of these systems is used as evidence that an operation exists, not as a
baseline to beat. **What we add:** for each operation, a postcondition and an externally
checkable evidence requirement, so that a system that lacks the operation is visible as a gap
rather than as a slightly lower accuracy number.

## 3. Retrieval: the read path is better understood than the rest

RAG (`\cite{lewis2020rag}`) established the read path and two surveys
(`\cite{gao2024ragsurvey}`, `\cite{zhao2024aigcsurvey}`) catalogue its variants and evaluation
axes. Retrieval quality is dominated by factors that are not the store's ranking function:
`\cite{liu2023lostmiddle}` shows a U-shaped dependence on where evidence sits in the context;
`\cite{hseih2024foundmiddle}` calibrates that positional bias; `\cite{asai2023selfrag}` makes
retrieval itself a decision with a critique signal; `\cite{edge2024graphrag}` and
`\cite{microsoftgraphrag}` derive a graph and summarise over communities;
`\cite{wang2024awm}` induces reusable workflows (procedural memory);
`\cite{xia2026hits}` compresses evidence, `\cite{xu2026contextpipe}` formalises context
assembly under a hard budget, and `\cite{zhao2025diverse}` treats diversity as a retrieval
objective. On the engineering side `\cite{xu2025harmony}` provides the vector-database
throughput bound that read latency inherits.

**Consequence for the protocol:** the read family must fix evidence position and context
budget, must record retrieved-token counts, and must score provenance separately — otherwise
a comparison between two stores measures the surrounding harness.

## 4. Conflict, revision and provenance

Knowledge conflicts are catalogued (`\cite{xu2024conflictsurvey}`) and benchmarked
(`\cite{su2024conflictbank}`); `\cite{chen2026ragwrong}` shows final-answer accuracy conceals
whether the model followed retrieved evidence, its parametric prior, or neither;
`\cite{schuster2026sourcepref}` shows source identity changes conflict resolution — hence the
source field must be part of a record. On the parametric side, `\cite{meng2022rome}` and
`\cite{meng2022memit}` edit internal factual associations (including mass edits), and
`\cite{wang2024editsurvey}` surveys the field; `\cite{kassner2021belief}` keeps belief
statements in an external structure to make a model consistent. Formal belief change supplies
the vocabulary: AGM revision and its Katsuno–Mendelzon-style characterisation
(`\cite{falakh2021agm}`), and the truth-maintenance lineage (`\cite{falkenhainer2013belief}`).
Provenance has a standard model in `\cite{prov_o}` and an agent-specific extension in
`\cite{souza2025provagent}`. The failure mode this paper centres on — an agent answering from a
record it should no longer use — is isolated and scored in `\cite{mullick2026store}` under
metamemory monitoring, while `\cite{panda2026twist}` proposes measuring the quality of memory
*interventions* rather than recall. The write path has an integrity literature:
`\cite{louck2026poisoning}` (non-malleable, origin-bound authority),
`\cite{sunil2026mempoison}` (memory poisoning attack and defence), `\cite{chen2026mrmmia}`
(membership inference against agent memory).

**What we take:** conflict classes, the source-authority variable, the stale-read failure, and
provenance vocabulary. **What we add:** these become measured metrics in one report, with the
revision policy stated in advance so "correct revision" is defined before the run.

## 5. Epistemic status and calibration

Verbalised confidence can be trained to be more informative than token probabilities
(`\cite{lin2022uncertaintywords}`); large models are reasonably calibrated on self-evaluation
and can predict what they will answer correctly (`\cite{kadavath2022know}`); the elicitation
strategy matters as much as scale (`\cite{tian2023justask}`); no single prompt strategy gives
both good calibration and good discrimination (`\cite{xiong2023confidence}`); assistants can
be calibrated to refuse outside their boundary (`\cite{cheng2024knownotknow}`); probabilistic
and verbalised confidence trade off (`\cite{ni2024probabilistic}`) and verbalised scores are
prompt-sensitive, so their evaluation needs an explicit protocol (`\cite{yang2024verbalized}`);
uncertainty can also be decomposed to drive clarification (`\cite{matsnev2026uncertdec}`).
Metric machinery comes from `\cite{guo2017calibration}` (ECE, reliability diagrams, temperature
scaling) and from the human-judgement literature on calibration vs. resolution
(`\cite{lichtenstein1982calibration}`); `\cite{kalman1960filter}` is the classical form of a
recursive estimate carrying its own uncertainty. On the store side, `\cite{feng2026baremem}`
stores per-record reliability and `\cite{sintepistemic}` implements a status vocabulary with a
calibration query.

**Consequence:** a stored confidence score without its elicitation method and its outcome is
not calibratable; the protocol therefore requires status, score, prompt hash and outcome to be
recorded together, and it forbids reporting ECE without discrimination.

## 6. Prospective memory: the operation that is usually absent

`\cite{einstein1990prospective}` established experimentally that executing a deferred
intention at a future cue is a distinct faculty. Twenty-six years later the agent literature
had to rebuild the concept: `\cite{liu2026pmbench}` introduces PM-Bench, a text benchmark for
measuring whether an intention fires at the right cue while other activity continues, and
`\cite{zhao2026pmslm}` reports that even the best published PM-Bench scaffold remains weak and
responds with typed intention stores. `\cite{sintprospective}` implements an intention stack
with suspend/resume, context markers and session snapshots.

**Consequence:** we do not invent a prospective-memory benchmark; we adopt the family and add
the *store-level* checks that a benchmark of answers cannot see — fire-once semantics, context
availability at fire time, and interference cost on the primary task.

## 7. Cognitive architecture: what is borrowed and what is refused

We borrow vocabulary only where it clarifies an interface: separate declarative and procedural
stores with activation-based retrieval (`\cite{laird2012soar}`, `\cite{anderson2004actr}`),
the detailed comparison of two architectures' representations and metadata
(`\cite{laird2022actrsoar}`) — evidence that store boundaries differ per architecture, which
is exactly why an operation-level taxonomy is more portable than a structural one —
declarative/procedural personalisation in a deployed system (`\cite{innerebner2025actr}`), generalisation across episodes as an operation
(`\cite{mohan2022analogical}`), the multi-store model with control processes
(`\cite{atkinson1968human}`), capacity limits (`\cite{miller1956magical}`), depth of processing
(`\cite{craik1972levels}`), encoding specificity (`\cite{tulving1973encoding}`), source
monitoring as a separable process (`\cite{johnson1993source}`), spacing effects
(`\cite{cepeda2008spacing}`), retrieval practice modifying retention
(`\cite{roediger2006testing}`), sleep-dependent consolidation (`\cite{walker2004sleep}`,
`\cite{whelan2021replay}`), and forgetting-curve-inspired schedules
(`\cite{kline2025forgetting}`, `\cite{feng2026forever}`).

**Refused claim:** that artificial memory should be made human-like. `\cite{wang2026simulating}`
runs classic memory experiments on language models and reports their memory is far *more*
reliable than human memory, and `\cite{pasukonis2022mazes}` evaluates retention in partially
observed environments without anthropomorphic assumptions. Decay and interference appear here
as *policy variants to be measured*, not as goals.

## 8. MCP and tool-level evaluation

MCP defines the interface this protocol binds to (`\cite{mcpintro}`,
`\cite{anthropicmcp2024}`, `\cite{mcpspec2025}`, earlier revision `\cite{mcpspec2025mar}`),
with JSON-RPC framing (`\cite{jsonrpc2}`) and a reference server collection
(`\cite{mcpservers}`). Evaluation of MCP servers already exists at task level:
`\cite{luo2025mcpbench}` (MCPBench: effectiveness and efficiency of widely used servers),
`\cite{luo2025mcpuniverse}` (231 tasks over real servers), `\cite{fan2025mcptoolbench}`
(large-scale tool use with cost analysis), `\cite{zong2025mcpsafety}` (safety with real
servers), `\cite{rodrigues2026mcppatterns}` (architecture patterns and ecosystem growth).
Two findings shape our methodology: `\cite{afsar2026registry}` shows ecosystem studies select
for servers that work (reference sets, popularity lists, repaired pipelines), and
`\cite{shi2025toolretrieval}` shows that as tool sets grow, *retrieving the right tool*
becomes the bottleneck. Metadata integrity is a live problem: `\cite{rashidi2026unicode}`
demonstrates tool-metadata payloads concealed with Unicode TAG-block characters across three
independent server implementations, and `\cite{lee2026citecheck}` shows a protocol server can
carry a machine-checkable verification procedure (bibliographic repair) — the closest thing in
the ecosystem to what we propose for memory records. Wider agent-protocol work
(`\cite{chang2025anp}`, `\cite{nie2026awcp}`, `\cite{garzon2025did}`) confirms that explicit,
testable interfaces are the direction of travel for agent infrastructure.

**Delta:** MCPBench and MCP-Universe measure an agent's ability to *use* servers. We measure a
memory server's *operations*, with the store itself as the subject and no model required in
the loop.

## 9. Memory evaluation benchmarks and what they miss

`\cite{wu2024longmemeval}` defines five long-term-memory abilities (information extraction,
multi-session reasoning, temporal reasoning, knowledge updates, abstention) over 500 questions;
`\cite{maharana2024locomo}` provides very long-term multi-session dialogue with QA and
event-graph summarisation and reports that long-context and RAG models lag humans;
`\cite{kim2024dialsim}` adds multi-party dialogue with time constraints;
`\cite{wu2025sgmem}` keeps sentence-level structure and provenance instead of reducing context
to isolated facts; `\cite{zhang2026beyondstatic}` argues for evolving personas and long-horizon
semantic consistency; `\cite{du2026ifcmemory}` argues that domain-specific evaluation is a
stronger test than persona-grounded open-domain recall; `\cite{lee2026aema}` proposes verifiable
evaluation of agentic systems; `\cite{trashchenkov2026power}` shows executable evaluation in
electric power engineering, i.e. checking consequences with a program rather than grading
prose. Two works are closest to our operation-level intent: `\cite{wang2026rightmemory}`
verifies retrieval *admissibility* (principal, policy, lifecycle) and shows recall and answer
accuracy cannot detect it, and `\cite{song2026eviction}` isolates a *pre-retrieval* retention
failure in which necessary evidence is evicted before any query arrives. On reporting practice,
`\cite{moghadasi2026disclose}` audits twelve agent benchmark papers and finds that two papers
can report different results on the same benchmark and model without the text explaining why
(scaffold, prompts, budget), and `\cite{rassheed2024multieval}` shows grader variance.

**Delta in one line:** these works each measure *an ability* or *a property*. This paper
proposes a single protocol whose unit is the operation, whose output is a validated report,
and whose subject can be any memory server — including one whose authors never heard of us.

## 10. Reference implementation (our own artefact)

The reference implementation is a set of public MCP servers (`\cite{sintrepo}`):
liquid memory with contradiction handling and revision chains (`\cite{sintliquid}`),
epistemic status with calibrated confidence (`\cite{sintepistemic}`), offline dreaming /
consolidation (`\cite{sintdream}`), prospective memory (`\cite{sintprospective}`) and a
role-based review swarm including provenance and uncertainty roles (`\cite{sintswarm}`).
Facts about these repositories — commit SHAs, tool counts, file inventory — are collected by
`code/repo_facts.py` into `data/repo-facts.json` at collection time `2026-10-16`, and the
operation coverage plus the four known gaps are listed in `taxonomy.md` §6. This artefact is
cited as an *implementation*, not as evidence of quality: the paper makes no accuracy claim
about it before a protocol run exists.
